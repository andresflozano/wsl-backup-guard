# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities, exposed secrets, or unsafe deletion behavior in a public issue. Use GitHub private vulnerability reporting when enabled.

Include the affected version or commit, reproduction steps using synthetic data, expected behavior, observed behavior, and impact. Never attach real archives, credentials, private keys, cloud account details, or customer data.

## Supported status

This repository is an initial public scaffold. No released version is currently declared supported.

## Sensitive data boundary

The repository must not contain:

- real WSL exports or encrypted backups;
- real checksum or manifest values from private machines;
- user profiles, home-directory names, or absolute personal paths;
- SSH, cloud, Git, Docker, browser, or application credentials;
- client or employer data, names, URLs, configuration, or code;
- screenshots containing account or storage information.
