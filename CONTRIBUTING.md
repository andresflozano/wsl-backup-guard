# Contributing

1. Use synthetic fixtures only.
2. Keep health checks read-only.
3. Add or update Pester tests for every behavior change.
4. Distinguish syntax, execution, and semantic validation.
5. Do not add automatic deletion, overwrite, password persistence, or unattended restore behavior without a separate design review.
6. Document the precise claim supported by each check and what remains unvalidated.

Pull requests should include scope, changes, performed validation, limitations, risks, and rollback considerations.
